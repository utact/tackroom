# kowrite

한국어 문서·주석·커밋의 규칙을 지키게 하는 플러그인이다.
세션을 시작할 때 규칙 다섯 줄을 지시하고, 1~4번을 어기면 훅이 알리거나 막는다.
규칙을 지키면 훅은 아무것도 출력하지 않는다.
모델은 호출하지 않는다.

## 규칙

**1. 문장은 짧게 쓰고, 한 문장이 끝나면 줄을 바꾼다.**

- 편집 직후에 알리고, 커밋 직전과 응답 종료 전에 막는다.
- Markdown은 이어진 줄을 한 문단으로 합치므로, 문단의 줄은 문장으로 끝나야 한다.
- 주석과 커밋 본문은 명사형 문체가 흔하므로, 조사, 연결 어미, 쉼표처럼 문장이 이어질 수밖에 없는 끝만 잡는다.

**2. 커밋 메시지에 도구·모델 표기와 세션 링크를 넣지 않는다.**

- 커밋 직전에 막는다.
- 사람 공동 작성자는 막지 않는다.

**3. 문서의 수치는 코드 상수와 묶는다.**

- 값 앞에 `<!-- const: 경로:상수 -->`를 붙인다.
- 값이 상수와 다르면 편집 직후에 알리고, 종료 전에 막는다.

**4. 코드를 설명하는 문서는 대상을 밝힌다.**

- 문서에 `<!-- tracks: 경로 -->`를 적는다.
- 대상 코드만 바뀌고 문서가 그대로면 종료 전에 막는다.

**5. 사용자나 저장소에서만 통하는 표현을 문서에 옮기지 않는다.**

- 대화에서 생긴 표현은 같은 뜻의 통용 용어로 바꿔 쓴다.
- 마땅한 용어가 없으면 처음 쓰는 곳에 정의를 먼저 적는다.
- 어떤 표현이 통용되는지는 기계적으로 가리기 어려우므로, 훅으로 검사하지 않고 세션 지침으로만 지시한다.

## 검사 범위

- 종료 전 검사는 세션을 시작한 시점의 작업 트리와 비교한다. 세션 전부터 있던 변경은 대상이 아니다.
- 같은 지적으로는 세션마다 한 번만 막는다. 새 지적이 생기면 다시 막는다.
- Stop 훅의 수정 후 재진입에서는 남은 지적을 기록하고 통과시킨다. 검사 오류도 세션을 차단하지 않는다. 최종 결과가 모든 규칙을 만족한다는 보장은 아니다.
- 코드 블록과 인라인 코드 안의 마커는 예시로 보고 검사하지 않는다.

## 요구 사항

bash(Windows는 Git Bash), Python 3.8 이상, git이 필요하다.
훅은 `python3`, `python`, `py` 순서로 Python을 찾는다.
