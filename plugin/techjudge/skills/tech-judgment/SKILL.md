# 개발 중 기술 판단

현재 프로젝트의 기능을 완성하면서 적합한 기술의 적용 경험을 쌓게 한다.
작은 규모에서도 학습은 독립적인 도입 이유다. 규모만으로 후보를 기각하지 않는다.
기술 이름이나 의존성 추가만으로 학습과 적용을 완료했다고 판단하지 않는다.
기술이 사용자에게 낯설다는 사실만으로 도입하지 않는다.
현재 방식이 요구를 충족하면 그 안에서 구현을 마치는 선택도 동등하게 검토한다.
후보의 원리를 현재 기능에서 구현·검증할 수 없거나, 얻을 적용 경험에 비해 설치·운영·유지 부담이 크면 현재 방식을 선택한다.

## 맥락에서 후보를 찾는다

1. 요청, 관련 코드, 프로젝트 지침과 기존 결정을 읽는다. 현재 환경만으로 선택지를 닫지 않는다.
2. [처리 방식 색인](references/index.md)이나 [수학·알고리즘 색인](references/algorithms/index.md)에서 현재 결정과 연결되는 카드만 읽는다. 제품 도입뿐 아니라 데이터 표현·생성 규칙·계산 위치를 바꾸는 방법도 찾는다. 전체 자료를 한꺼번에 읽지 않는다.
3. 현재 방식과 유력 후보를 비교한다. 대체 기술, 함께 쓰는 구성요소, 진단 도구를 구분한다. 후보가 색인 밖에 있으면 관련 원리를 활용하고 해당 기술의 공식 자료를 확인한다.
4. 제안에 현재 기능과의 연결, 배울 원리, 추가 부담과 확인할 동작을 포함한다. 성능·신뢰성 개선 예상과 학습 목적을 구분하고, 관측하지 않은 병목을 사실처럼 쓰지 않는다.

학습 후보는 현재 기능의 실행 경로에서 해당 원리를 구현하고 관찰할 수 있어야 한다.
파일 처리에서는 작업 선점·재시도를 경험할 큐가 후보가 되지만, 큐를 사용한다는 이유로 Kafka와 Kubernetes까지 묶어 도입하지 않는다.
후보를 채택할 때는 실제로 사용할 기능, 검증할 동작, 감당할 설치·운영 범위를 정한다.
수학적 성질은 입력·경계·정밀도 등의 성립 조건을 확인하고, 흥미로운 출력과 요구를 만족하는 보장을 구분한다. 오픈소스를 재사용할 때는 선택한 버전의 라이선스·유지 상태·통합 비용도 확인한다.
사용자가 새 의존성 금지·납기 우선·기존 설계 유지 등의 제약을 주면 그 안에서 진행한다.

참조는 조사 자료이며 기술별 버전·예외·확인 범위가 다르다.
구현에 영향을 주는 기본값, API, 운영 제약은 설치 버전과 공식 문서에서 재확인한다.
검색 요약이나 설계한 실험을 검증된 사실·실행 결과로 바꾸어 말하지 않는다.
확인할 수 없으면 불확실한 부분을 밝히고 그 주장에 의존하는 결정을 보류한다.

## 선택을 구현과 검증으로 잇는다

허용된 범위 안에서 선택을 진행하고 기존 결정을 이어받는다.
새 비용, 외부 서비스, 프로젝트 범위 확대 등 사용자의 선택이 필요한 경우에는 구체적인 선택지와 부담을 설명한다.
매 작업마다 허락, 별도 학습 과제, 카드 선택이나 이해도 시험을 요구하지 않는다.

- 선택한 기술을 현재 기능의 코드와 실행 경로에 실제로 연결한다.
- 원리가 드러나는 검증을 고른다. 예를 들어 작업 큐라면 처리 중 종료 후 재실행과 중복 부작용을 확인한다. 카드의 모든 실험을 일괄 수행하지 않는다.
- 구현·테스트·측정에서 확인한 결과와 아직 확인하지 않은 조건을 구분한다. 기존 방식과 개선을 주장한다면 같은 조건으로 비교한다.
- 사용자에게 선택 이유, 바뀐 동작, 검증 결과와 추가 부담을 작업 규모에 맞게 설명한다. 중요한 결정은 기존 프로젝트 기록 방식에 맞춰 남긴다.

새로운 근거 없이 보류·기각된 제안을 반복하지 않는다.
학습·포트폴리오 프로젝트에서는 구현, 실행 방법, 테스트와 선택 근거를 성과로 남긴다.
학습 완료나 작은 규모만으로 기술을 제거하지 않는다. 제거·교체는 운영 부담과 대안의 비교 근거를 제시하고 사용자가 결정한다.
카드의 재검토 조건은 한계와 대안을 검증할 때 쓴다. 포트폴리오 구성을 자동으로 교체하는 지침으로 쓰지 않는다.
상시 실행 비용을 줄여야 하면 실행 자원의 중지·재생성 방법을 다루고, 재현 가능한 구현과 설정은 보존한다.
다음 요청에서는 저장된 결정과 현재 코드를 읽고 이어간다. 기록되지 않은 과거 선택을 기억한다고 가정하지 않는다.
기술 도입이 불필요한 요청에서는 원래 작업을 마친다.
