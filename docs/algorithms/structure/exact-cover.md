# 정확 덮개·Algorithm X·Dancing Links

확인: 2026-10-04.

## 요약

여러 선택지로 모든 필수 조건을 정확히 한 번 충족하는 문제를 푼다. Algorithm X는 되돌아가는 탐색 절차이고 Dancing Links는 희소 연결 구조에서 삭제·복원을 효율적으로 수행하는 구현이다.

## 문제 신호

조각 배치, 슬롯 배정, 퍼즐처럼 중복 없이 전체를 채워야 하고 작은 사례에서 해 존재 여부를 확인하려는 경우다.

## 기준선의 한계

탐욕적으로 다음 조각을 놓으면 마지막 조건이 불가능해질 수 있다. 모든 조합을 무조건 열거하는 기준선은 단순하지만 중복 검사와 상태 복사 비용이 커진다.

## 원리

조건을 열, 선택지를 행으로 하는 0·1 행렬을 만든다. 한 열을 고르고 이를 덮는 행을 선택한 뒤, 선택한 행이 덮은 열과 충돌하는 행을 제거한다. 재귀 탐색 후 제거를 역순으로 복원한다. Dancing Links는 네 방향의 연결을 보존해 되돌리며 후보가 가장 적은 열을 고르는 전략과 결합할 수 있다.

## 가치

탐색 엔진과 도메인 모델을 분리한다. 모든 해를 열거하거나 해가 없음을 작은 완전 탐색으로 확인하는 데 적합하다.

## 트레이드오프와 리스크

희소 표현이 탐색의 지수적 증가를 없애지는 않는다. 행을 만드는 과정 자체가 거대해질 수 있고, 복원 순서의 오류는 다음 분기의 결과를 훼손한다. 정확 덮개로 표현되지 않은 조건은 보장하지 않는다.

## 대안과 경계

부등식·목적 함수가 많으면 SAT·정수계획·제약 프로그래밍을 비교한다. 국소 타일 생성은 [WFC](pattern-synthesis.md)와 목적이 다르다. 일반화된 덮개에서는 필수 열은 정확히 한 번, 보조 열은 최대 한 번 덮도록 구분한다.

## 깊이 있는 활용

타일 배치에서 각 칸과 조각 사용을 필수 열로 만들고, 교차 금지를 보조 열로 모델링할 수 있다. 중복 해를 줄이려면 [그래프 정규화](canonical-graphs.md) 또는 허용 대칭의 대표 선택을 추가 검토한다.

## 임시방책의 신호

잘못된 답이 나오면 탐색 제한만 늘리거나, 조건을 행렬 밖의 사후 검사에 계속 쌓는 경우다. 모델 누락과 탐색 중단을 해 부재로 보고하지 않는다.

## 실패 재현

제안 실험: 작은 행렬의 모든 부분집합을 열거한 결과와 Algorithm X를 비교한다. 일부 분기에서 복원 순서를 바꾼 구현은 해를 누락할 수 있다. 후보 행이 없는 필수 열과 선택적인 보조 열을 각각 넣는다.

## 측정과 검증

해의 조건 충족, 해 개수, 탐색 노드 수, 복원 후 상태 동일성, 행렬 구성 메모리를 확인한다. 완전 탐색 종료와 시간 제한 종료를 따로 기록한다. 논문 절차를 확인했으며 여기서 DLX 구현을 실행하지 않았다.

## 재검토 조건

선택지 생성 비용이 지배하거나 최적해가 필요하면 목적 함수가 있는 해결기를 비교한다. 증분 변경이 잦으면 전체 재구성과 상태 재사용의 정확성을 다시 검토한다.

## 출처

- [Knuth, Dancing Links, 2000](https://arxiv.org/pdf/cs/0011047): 정확 덮개 행렬, Algorithm X, 삭제·복원, 최소 후보 열과 필수·보조 열의 본문을 확인했다. 논문의 과거 실행 시간을 현재 성능으로 인용하지 않는다.
