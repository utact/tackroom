# 포켓몬 그림 압축의 평면·차분·RLE

확인: 2026-10-04.

## 요약

제한된 색 그림을 비트 평면으로 나누고 가역 변환으로 반복을 드러낸 뒤 부호화한다. 포켓몬 공개 복원 구현은 평면 순서·변환 모드를 비교해 작은 결과를 선택한다.

## 문제 신호

작은 4색 스프라이트의 구조를 이용한 압축을 실험하거나, 가역 변환과 실제 부호화의 역할을 구분하려는 경우다.

## 기준선의 한계

픽셀의 2비트 표현만으로도 값 영역은 줄지만 반복과 이웃 상관은 사용하지 않는다. 원본 2bpp와 팔레트 PNG를 기준선으로 비교한다.

## 원리

입력 타일을 재배열하고 2bpp의 두 평면을 분리한다. 모드에 따라 평면 간 XOR와 이전 비트 상태에 따른 Gray 변환을 사용한다. 2비트 묶음을 순회하며 연속된 0은 길이 부호로, 나머지는 데이터 묶음으로 쓴다. 압축기는 모드·평면 순서를 시험하고 복원기는 저장된 선택을 역변환한다.

## 가치

색 영역·이웃 상관·평면 상관을 단계별로 활용하는 예제다. 변환 전후의 0 구간 변화와 전체 부호 길이를 직접 비교할 수 있다.

## 트레이드오프와 리스크

읽은 구현은 정사각형이며 크기와 타일 배열에 제한이 있다. 잡음 같은 입력은 반복이 적다. 복원 작업 메모리와 잘못된 입력의 길이 검사가 필요하다. 저장 코덱만으로 GPU 메모리는 줄지 않는다.

## 대안과 경계

호환성과 제작 도구가 중요하면 [PNG·QOI](lossless-codecs.md), 실행 중 상주량이면 [GPU 텍스처 압축](gpu-textures.md)을 비교한다. [팔레트·타일 표현](palette-tiles.md)은 이 코덱의 입력 구조를 설명한다.

## 깊이 있는 활용

각 변환을 제거한 실험으로 차분·XOR·RLE의 기여를 분리한다. 새 코덱을 만들 때는 이 구조에서 원리만 가져오고 원본 형식 호환 여부를 별도로 정한다.

## 임시방책의 신호

선택한 그림 몇 장의 압축률을 모든 자산에 일반화하거나, 직접 개발한 구현을 원본 게임의 개발 코드라고 설명하는 경우다.

## 실패 재현

제안 실험: 단색·줄무늬·두 평면이 같은 그림·독립 잡음을 만든다. 모든 허용 모드의 크기를 비교하고 복원 바이트가 원본과 같은지 검사한다. 지원하지 않는 가로·세로 크기는 명시적으로 거절한다.

## 측정과 검증

왕복 복원의 바이트 일치, 모드별 크기, 인코딩·복원 시간과 최고 작업 메모리를 측정한다. 같은 그림의 PNG·원본 2bpp와 비교한다. 소스를 읽었으며 복원 도구를 실행한 결과는 없다.

## 재검토 조건

해상도·색 수·비정사각형·애니메이션이 추가되면 형식의 제한과 코덱 유지 부담을 재검토한다. 데이터를 바꿀 때는 복원기 호환 버전을 함께 기록한다.
