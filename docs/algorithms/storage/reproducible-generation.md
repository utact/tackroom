# 카운터 난수와 재생성·변경분 저장

확인: 2026-10-04.

## 요약

같은 입력을 같은 결과로 만드는 생성기를 저장 표현으로 활용한다. 카운터 기반 난수는 키와 카운터에 대한 함수이며 호출 순서와 난수 상태를 분리한다. 생성기 버전과 변경분을 함께 보존해야 전체 결과를 재현한다.

## 문제 신호

생성 자산이 많거나 방문 순서·병렬 실행과 무관한 구역 재현, 큰 원본 대신 작은 생성 입력의 저장이 필요한 경우다.

## 기준선의 한계

순차 난수 하나를 공유하면 호출을 추가하거나 방문 순서를 바꿀 때 뒤의 결과가 달라진다. 모든 생성 결과를 저장하는 기준선은 단순하고 안정적이지만 크기가 커질 수 있다.

## 원리

Random123은 counter·key를 받아 결정적인 정수 묶음을 반환한다. 좌표·대상 ID·용도·표본 번호를 충돌 없이 매핑하면 각 값에 독립적으로 접근할 수 있다. 기본 생성 결과 위의 사용자 변경은 대상 식별과 생성 버전을 포함해 저장한다. 이 저장 설계는 난수 함수의 성질을 이용한 응용이다.

## 가치

병렬 처리와 재방문의 난수 순서 의존을 줄인다. 그림·지형 전체 대신 생성 입력을 저장할 가능성을 비교할 수 있다.

## 트레이드오프와 리스크

생성기·분포 변환·부동소수점·자산 버전이 바뀌면 결과가 달라질 수 있다. 변경 대상 ID가 새 생성 결과에서 바뀌면 변경분이 잘못 적용된다. 카운터 난수는 암호학적 비밀 생성에 사용하지 않는다.

## 대안과 경계

작고 변경이 많은 자산은 전체 저장이 더 단순하다. 원본과 변경분 저장량·재생성 시간·구버전 유지 부담을 비교한다. 동일 바이트의 캐시는 [콘텐츠 주소](../systems/content-addressing.md)와 연결된다.

## 깊이 있는 활용

지형·식생·장식의 난수 용도를 분리하면 장식 추가가 지형을 바꾸는 일을 줄일 수 있다. 필요한 구역만 재생성하고 자주 쓰는 결과를 캐시한다. 구역 경계는 공통 좌표 규칙으로 생성한다.

## 임시방책의 신호

시드 하나만 기록하고 영구 재현을 약속하거나, 난수 출력의 재현과 전체 생성 결과의 재현을 혼동하는 경우다.

## 실패 재현

제안 실험: 같은 구역을 다른 방문 순서·작업자 수로 생성한다. 순차 난수와 카운터 매핑을 비교하고 생성기 버전을 바꾼 뒤 이전 변경분을 적용해 대상 일치를 확인한다.

## 측정과 검증

입력·버전별 결과 해시, 순서 변경 불변성, 경계 일치, 변경분 적용과 재생성 지연을 검사한다. 알려진 난수 정답과 전체 생성 결과 검사는 별도로 한다. Random123을 실행한 결과는 없다.

## 재검토 조건

장기 보존·동기화·생성기 업데이트가 필요하면 구버전 유지와 결과 스냅샷의 비용을 비교한다. 새로운 난수 용도에는 매핑 규칙을 먼저 정의한다.
