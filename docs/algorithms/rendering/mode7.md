# Mode 7과 주사선별 평면 투영

확인: 2026-10-04.

## 요약

배경의 표본 좌표를 아핀 변환해 회전·확대·이동을 표현한다. 주사선마다 변환 계수를 바꾸면 평평한 바닥의 원근감을 연출할 수 있다. 배경 변환만으로 일반적인 3D 공간을 만들지는 않는다.

## 문제 신호

2D 타일 배경에서 회전하는 지도나 원근 바닥을 표현하고, 오래된 하드웨어의 좌표 표현을 학습하려는 경우다.

## 기준선의 한계

전체 그림의 균일 확대·회전은 간단하지만 위쪽과 아래쪽의 거리 차이를 표현하지 못한다. 일반 3D 렌더러는 더 많은 기하·카메라 기능을 제공하지만 비교할 구현 범위가 커진다.

## 원리

화면 좌표를 행렬 계수 a·b·c·d와 중심·오프셋으로 배경 좌표에 옮기고 타일·팔레트를 읽는다. 고정된 행렬은 아핀 변환이며 원근 나눗셈을 포함하지 않는다. 행별로 계수를 달리하는 평면 역투영을 설계하면 화면 위치에 따라 축척이 변한다.

## 가치

좌표 변환·고정소수점·표본화의 관계를 작게 구현할 수 있다. 같은 타일 데이터에서 카메라 연출만 바꾸는 학습에 적합하다.

## 트레이드오프와 리스크

지평선 부근의 축척, 표본화 계단, 배경 경계와 정수 정밀도가 문제다. 벽·언덕·교차하는 물체의 기하는 따로 필요하며 충돌과 화면 투영의 좌표를 일치시켜야 한다.

## 대안과 경계

고정 위쪽 시점은 [직교 투영](projection-parallax.md)으로 충분할 수 있다. 높이가 있는 공간과 자유로운 카메라는 실제 3D 기하를 비교한다. 주사선별 깊이 연출을 Mode 7의 단일 아핀 행렬 자체의 성질로 설명하지 않는다.

## 깊이 있는 활용

소프트웨어로 바닥 평면의 역투영을 구현하고 아핀 변환과 행별 축척을 단계적으로 비교한다. 배경 타일 재사용은 [타일 표현](../storage/palette-tiles.md)과 연결한다.

## 임시방책의 신호

특정 화면 크기에 맞춘 숫자만 남거나, 시각적으로 맞는 바닥 좌표와 실제 이동 좌표가 어긋나는 경우다.

## 실패 재현

제안 실험: 격자 무늬에 고정 행렬을 적용한 결과와 행별 축척을 적용한 결과를 비교한다. 배경 밖 표본을 반복·투명 처리하는 두 방식과 지평선 가까운 행을 확인한다.

## 측정과 검증

알려진 점의 화면·배경 좌표, 역변환 오차, 경계 처리, 정수·실수 구현의 차이와 프레임 시간을 기록한다. bsnes 코드를 읽었으며 에뮬레이터 실행·하드웨어 재현은 하지 않았다.

## 재검토 조건

높이 지형이나 카메라 기울기의 범위가 늘면 평면 가정과 정밀도를 다시 검토한다. 특정 기기 호환성이 필요하면 해당 레지스터와 타이밍을 별도로 검증한다.

## 출처

- [bsnes mode7.cpp](https://github.com/bsnes-emu/bsnes/blob/master/bsnes/sfc/ppu-fast/mode7.cpp): 행 좌표, 행렬·중심·오프셋 계산과 타일·팔레트·경계 처리를 확인했다. 기본 브랜치의 에뮬레이터 구현이며 원본 게임의 개발 코드가 아니다. 주사선별 원근 구성은 이 평면 변환을 확장한 설계 설명이다.
