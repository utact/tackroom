# URL 상태 공유와 클라이언트 처리

확인: 2026-10-04.

## 요약

작은 상태를 주소에 직렬화하거나 데이터가 있는 기기에서 먼저 처리해 저장·중계 역할을 줄인다. 공유·복원, 서버의 기준 상태, 클라이언트 계산은 서로 다른 책임이다.

## 문제 신호

계산기·필터·지도 설정을 링크로 복원하거나 파일의 미리보기·압축 때문에 서버와 화면이 모두 바빠지는 경우다.

## 기준선의 한계

모든 임시 설정을 서버에 저장하면 API·계정·보존 작업이 생긴다. 모든 파일을 앱 서버가 중계하고 처리하면 원본 전송과 서버 계산 부담이 커질 수 있다.

## 원리

URLSearchParams는 이름·값을 직렬화해 주소가 상태를 운반하게 한다. 스키마 버전·기본값·중복 키·유효 범위를 정한다. Web Worker는 계산을 별도 실행 맥락으로 옮기고 메시지로 결과를 전달한다. 복사와 버퍼 소유권 이전을 구분한다. 저장소 직접 업로드는 권한 발급과 데이터 전송 경로를 나눈다.

## 가치

작은 도구의 공유·복원 기능과 미리보기 계산을 독립적으로 구현할 수 있다. 처리 위치를 바꾸며 서버 비용과 기기 지연의 교환을 관찰한다.

## 트레이드오프와 리스크

주소 길이·인코딩·주소 공개와 구버전 복원이 문제다. URL만으로 최신 공동 상태나 접근 제어가 생기지 않는다. 기기 연산은 배터리·메모리·중단·기기 성능 편차를 부담한다. 클라이언트 결과를 업무상 신뢰할 수 있는지는 별도 판단이다.

## 대안과 경계

공동 편집·권한·영구 기록은 서버 상태와 비교한다. 직접 업로드의 권한·완료 검사·중단 복구는 기존 [파일 업로드 카드](../../stacks/storage/file-upload.md)를 읽는다. 상태가 크면 주소에는 식별자만 담는 방식도 비교한다.

## 깊이 있는 활용

입력 상태의 정규 직렬화와 구버전 변환을 정의하면 공유 링크를 회귀 입력으로 사용할 수 있다. 미리보기는 Worker로 옮기고 필요한 최종 검증은 서버에서 수행하는 등 결과의 용도에 맞춰 책임을 나눈다.

## 임시방책의 신호

주소를 데이터베이스라고 부르며 공동 상태 보장을 기대하거나, Worker 사용만으로 서버 비용·전체 계산량이 사라진다고 설명하는 경우다.

## 실패 재현

제안 실험: 한글·공백·더하기 기호·중복 키와 구버전 링크를 왕복 복원한다. 큰 버퍼의 복사와 이전을 비교하고 작업 중 페이지 종료·입력 변경을 넣어 오래된 결과가 반영되는지 확인한다.

## 측정과 검증

상태 왕복 일치, 잘못된 입력 거절, 링크 길이, 화면 응답성, 기기 계산·전송량과 서버 검증 범위를 확인한다. 브라우저에서 실행한 측정은 없다.

## 재검토 조건

상태 크기·비밀 정보·공동 수정·기기 지원이 바뀌면 저장 위치를 다시 검토한다. 데이터 소유권 이전과 취소·재시도 정책을 실제 브라우저에서 확인한다.

## 출처

- [WHATWG URL Standard](https://url.spec.whatwg.org/#urlsearchparams): URLSearchParams와 form 인코딩·더하기 기호 처리를 확인했다.
- [WHATWG HTML Workers](https://html.spec.whatwg.org/multipage/workers.html): 실행 맥락, 메시지 복사·이전과 종료 API를 확인했다. 두 자료는 Living Standard로 특정 브라우저 버전을 고정하지 않았다.
