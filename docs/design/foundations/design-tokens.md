# 디자인 시스템과 토큰

확인: 2026-10-04.

## 요약

색·서체·간격의 값을 역할별 토큰으로 관리하고 컴포넌트의 상태·동작과 연결한다.

## 문제 신호

같은 오류·선택 상태가 화면마다 다른 색과 간격으로 표현된다.

## 기준선의 한계

색상 값만 나열하면 오류·선택·표면의 역할과 테마별 상태를 추적하기 어렵다.

## 원리

기초 값과 의미별 별칭을 구분한다. DTCG 2025.10은 타입·값·그룹·참조를 교환하는 JSON 형식을 정의한 커뮤니티 보고서이며 W3C 표준 권고안은 아니다.

## 가치

디자인과 코드에서 같은 역할의 값을 추적하고 변경 범위를 줄인다.

## 트레이드오프와 리스크

토큰의 수가 많으면 이름·참조·변환 관리가 부담이다. 형식 일치가 화면 품질이나 도구 간 완전한 호환성을 보장하지 않는다.

## 대안과 경계

작은 제품은 기존 테마 변수로 시작할 수 있다. 여러 플랫폼·도구에 전달할 때 교환 형식을 비교한다.

## 깊이 있는 활용

오류·강조·표면·본문 같은 의미를 먼저 정하고 테마별 실제 값을 매핑한다.

## 임시방책의 신호

화면 이름마다 색을 복제하거나 토큰을 만들고도 코드에 값을 다시 직접 쓴다.

## 실패 재현

별칭을 순환시키거나 토큰 하나를 바꿔 예상 밖의 화면까지 변하는 사례를 재현한다.

## 측정과 검증

참조 해석, 테마별 대비, 영향 화면과 내보내기·가져오기 결과를 확인한다.

## 재검토 조건

여러 브랜드·플랫폼·디자인 도구를 지원하면 토큰 계층과 변환 범위를 재검토한다.
