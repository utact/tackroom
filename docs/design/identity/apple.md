# Sign in with Apple 버튼

확인: 2026-10-04.

## 요약

Apple 로그인은 시스템 버튼과 해당 플랫폼의 공식 사용 지침을 기준으로 설계한다.

## 문제 신호

Apple 심볼을 바꾸거나 로그인 문구·보이스오버 이름을 임의로 구성한다.

## 기준선의 한계

검은색 둥근 버튼이라는 외형만 복제하면 문구·배치·접근성 요구가 누락된다.

## 원리

네이티브는 SignInWithAppleButton 또는 ASAuthorizationAppleIDButton을 검토한다. 웹·다른 플랫폼의 사용자 정의 버튼은 HIG의 로고·문구·비율 조건을 확인한다.

## 가치

플랫폼의 익숙한 계정 진입과 현지화·접근성 지원을 활용한다.

## 트레이드오프와 리스크

네이티브·웹의 제공 방식과 서비스 연결 조건이 다르다. HIG 권장 UX와 서비스 사용 요건을 구분한다.

## 대안과 경계

시스템 버튼과 공식 웹 구현을 비교한다. 앱 브랜드로 Apple 심볼을 다시 그리지 않는다.

## 깊이 있는 활용

계정이 필요한 시점, 취소, 기존 계정 연결을 버튼 이후의 흐름과 함께 설계한다.

## 임시방책의 신호

첫 화면의 모든 행동을 로그인으로 막거나 외형만 맞춘 버튼에 기능을 연결한다.

## 실패 재현

로그인 취소와 기존 계정 연결 상황에서 사용자가 다음 행동을 선택할 수 있는지 확인한다.

## 측정과 검증

승인된 버튼 표현, 접근성 이름, 계정 연결 동의와 로그인 결과 처리를 확인한다.

## 재검토 조건

배포 플랫폼·서비스 설정이 바뀌면 해당 플랫폼의 사용 요건을 재확인한다.
