# 전환·마이크로인터랙션·모션 감소

확인: 2026-10-04.

## 요약

모션의 목적을 상태 전달·공간 관계·주의 유도로 정하고 입력과 수명에 연결한다.

## 문제 신호

모든 요소가 움직이거나 화면을 닫은 뒤에도 애니메이션과 이벤트가 실행된다.

## 기준선의 한계

장식용 반복 재생만으로는 작업 상태를 설명하지 못하며 조작을 지연시킬 수 있다.

## 원리

웹의 CSS 전환·애니메이션·Web Animations API와 네이티브 전환을 비교한다. WAAPI는 키프레임과 재생 제어를 제공하며 모션 감소 설정에는 움직임을 줄인 표현을 제공한다.

## 가치

화면·상태 전환의 관계를 설명하고 조작 결과를 확인하게 한다.

## 트레이드오프와 리스크

시차·확대·큰 이동은 사용자에게 부담이 될 수 있다. transform·opacity 사용만으로 모든 환경의 성능을 보장하지 않는다.

## 대안과 경계

즉시 상태 전환이 기준선이다. 단순 전환은 기존 런타임, 복잡한 그래픽은 Lottie·Rive·영상을 비교한다.

## 깊이 있는 활용

취소·빠른 반복 입력·이탈·일시 정지에서 논리 상태와 시각 상태를 일치시킨다.

## 임시방책의 신호

모션을 끝까지 봐야 클릭할 수 있거나 모션 감소에서 필수 상태까지 숨긴다.

## 실패 재현

빠르게 열기·닫기·탭 전환을 반복하고 모션 감소 설정을 켠다.

## 측정과 검증

상태 일치, 입력 지연, 화면 밖 실행과 감소 모드의 정보 보존을 확인한다.

## 재검토 조건

모션이 입력·상태 분기를 맡게 되면 단순 타임라인과 상태 기반 재생을 다시 비교한다.

## 출처

- [MDN Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API), [prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion): 재생 제어와 사용자 설정.
