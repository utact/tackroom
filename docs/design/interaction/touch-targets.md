# 터치·포인터 대상 크기

확인: 2026-10-04.

## 요약

조작 대상(Target)의 크기와 간격을 입력 방식에 맞춰 정한다. 보이는 아이콘, 입력을 받는 영역(Hit Area), 피드백을 그리는 범위는 서로 다를 수 있다.

## 문제 신호

작은 아이콘을 자주 빗누르거나 인접한 버튼이 대신 실행된다.

## 기준선의 한계

이미지 해상도와 시각적 크기만으로 실제 조작 영역을 알 수 없다.

## 원리

Android는 최소 48×48dp의 터치 영역을 권장하고 Apple의 터치 UI 안내는 44×44pt를 제시한다. WCAG 2.2 AA의 SC 2.5.8은 포인터 대상에 24×24 CSS px를 요구하되 간격·동등한 기능·인라인·사용자 에이전트·필수 표현 예외가 있다.

## 가치

화면의 표현 밀도를 유지하면서 정확히 조작할 수 있는 영역을 확보한다.

## 트레이드오프와 리스크

dp·pt·CSS px와 이미지 픽셀은 같은 단위가 아니다. 플랫폼 권장 크기와 웹 적합성 하한을 하나의 수치로 합치지 않는다.

## 대안과 경계

내장 컴포넌트의 입력 영역을 기준선으로 삼는다. 영역 확장과 배치 간격 확대를 비교하고 [피츠의 법칙](../cognition/fitts.md)은 별도의 움직임 분석에 사용한다.

## 깊이 있는 활용

Compose는 작은 클릭 요소의 터치 영역을 경계 밖으로 확장할 수 있다. 인접 영역의 겹침을 확인하고 필요한 최소 배치 크기를 확보한다.

## 임시방책의 신호

보이지 않는 입력 영역만 넓혀 이웃 버튼과 겹치게 하거나 CSS 확대 효과를 조작 영역 확대로 간주한다.

## 실패 재현

아이콘 중앙·가장자리·사이 공간을 손가락·펜·마우스로 조작하고 확대·좁은 화면을 비교한다.

## 측정과 검증

실제 입력 판정 범위, 인접 대상 오조작, 최소 크기·간격과 적용 예외를 확인한다.

## 재검토 조건

레이아웃 밀도·입력 방식·내장 컴포넌트 버전이 바뀌면 영역 확장과 간격을 다시 검사한다.

## 출처

- [Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults): 48dp와 자동 터치 영역 확장·겹침.
- [Apple UI Design Dos and Don’ts](https://developer.apple.com/design/tips/): 터치 UI의 44pt 안내.
- [WCAG 2.2 SC 2.5.8 해설](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 24 CSS px와 예외.
