# 누름 상태와 상호작용 피드백

확인: 2026-10-04.

## 요약

누름 상태(Pressed State)는 입력 중임을 전달한다. 호버·초점·선택 상태와 작업 성공·실패를 구분한다.

## 문제 신호

버튼을 눌러도 반응이 없거나 손가락을 바깥으로 옮겨 취소했는데 누른 표현이 남는다.

## 기준선의 한계

클릭 뒤 색을 바꾸는 방식만으로 입력의 시작·해제·취소와 접근성 초점을 표현할 수 없다.

## 원리

리플(Ripple), 상태 오버레이, 강조·크기·경계 변화로 누름을 표시할 수 있다. Compose의 Press·Release·Cancel 상호작용과 Indication은 입력 상태와 그 표현을 분리한다.

## 가치

입력을 받았는지 즉시 알 수 있고 취소·완료의 동작을 예측하기 쉽다.

## 트레이드오프와 리스크

누름 피드백은 서버 작업의 성공을 뜻하지 않는다. 과한 축소·움직임은 가독성과 조작을 방해하고 햅틱만으로 상태를 전달할 수는 없다.

## 대안과 경계

플랫폼의 내장 표현을 기준선으로 삼는다. 사용자 정의 효과는 [모션 감소](../media/motion.md), 입력 방식과 유지 비용을 비교한다.

## 깊이 있는 활용

시각적 경계·입력 영역·효과의 클리핑 범위를 따로 정한다. 햅틱은 지원 장치와 사용자 설정을 존중하며 다른 피드백을 보완한다.

## 임시방책의 신호

효과를 없앤 뒤 대체 상태를 제공하지 않거나 누름·선택·로딩에 같은 표현을 쓴다.

## 실패 재현

빠른 연속 누름, 누른 채 바깥으로 이동, 취소, 키보드 실행과 느린 요청을 재현한다.

## 측정과 검증

입력에 대한 즉시 반응, 해제·취소 후 복귀, 초점의 구별과 작업 상태의 일치를 확인한다.

## 재검토 조건

입력 장치·애니메이션·컴포넌트 API가 바뀌면 상태 수명과 효과 범위를 재검토한다.

## 출처

- [Android 햅틱 API](https://developer.android.com/develop/ui/views/haptics/haptics-apis): 행동별 피드백과 사용자 설정.
