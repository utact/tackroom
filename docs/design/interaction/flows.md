# 단계별 입력·온보딩·완료

확인: 2026-10-04.

## 요약

작업을 나누는 단계와 필수·선택 정보를 정하고 이전 단계로 돌아갈 수 있게 한다.

## 문제 신호

처음부터 많은 입력을 요구하거나 뒤로 이동하면 입력을 다시 해야 한다.

## 기준선의 한계

화면 수만 줄이거나 늘리면 실제 작업량과 복구 부담을 줄이지 못한다.

## 원리

여러 페이지의 폼은 단계·현재 위치·다음 행동을 알려 준다. 단계 분기는 실제 작업 관계에 맞추고 완료 전에 필요한 내용을 검토할 수 있게 한다.

## 가치

사용자가 진행 상황과 남은 부담을 알고 작업을 이어 간다.

## 트레이드오프와 리스크

페이지 수가 많으면 전환 비용이 늘고 너무 적으면 한 화면의 부담이 커진다. 진척 표시가 실제 작업량을 과장하지 않게 한다.

## 대안과 경계

짧은 작업은 한 화면으로 유지한다. 독립된 묶음·분기가 있는 경우 단계형과 점진적 공개를 비교한다.

## 깊이 있는 활용

단계별 유효성, 입력 보존, 건너뛰기와 최종 제출의 상태를 정의한다.

## 임시방책의 신호

소개 화면을 모두 필수로 만들거나 다음 단계마다 이전 내용을 지운다.

## 실패 재현

중간 단계 새로고침·뒤로 이동·검증 실패와 재진입을 확인한다.

## 측정과 검증

완료 경로, 입력 손실, 필수 정보 이해와 중도 복구를 확인한다.

## 재검토 조건

분기·입력량·사용자의 숙련도가 달라지면 단계와 안내를 재검토한다.
