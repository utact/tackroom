# 미저장 변경과 이탈 보호

확인: 2026-10-04.

## 요약

미저장 변경(Unsaved Changes)을 저장 완료 상태와 구분하고, 이탈 시 보존·저장·버리기 경로를 설계한다.

## 문제 신호

작성 중 뒤로 가면 내용이 사라지거나 자동 저장 요청이 실패했는데 저장됐다고 표시된다.

## 기준선의 한계

변경 이벤트나 저장 버튼 클릭만으로 미저장 상태와 실제 저장 완료를 판단할 수 없다.

## 원리

현재 내용과 마지막 저장 완료 내용을 비교한다. 저장 중·실패·충돌을 별도 상태로 다룬다. 웹 문서 이탈의 beforeunload는 브라우저가 정한 문구만 표시하고 모바일에서는 항상 발생하지 않는다.

## 가치

실수로 나가도 작업을 보존하고 저장 결과를 확인할 수 있다.

## 트레이드오프와 리스크

변경을 모두 경고하면 불필요한 중단이 생긴다. 자동 저장·초안 보존에는 저장 범위·민감 정보·다른 기기와의 충돌 처리가 필요하다.

## 대안과 경계

자동 저장·초안 복구와 명시적 이탈 확인을 비교한다. 앱 내부 화면 이동, 브라우저 문서 종료와 네이티브 뒤로 가기는 각각 처리한다.

## 깊이 있는 활용

위험이 있는 이탈에서는 ‘저장하고 나가기’, ‘저장하지 않고 나가기’, ‘계속 편집’처럼 결과를 구분한다. iOS의 여러 선택지는 해당 플랫폼의 액션 시트 관례도 비교한다.

## 임시방책의 신호

경고를 한 번 띄우면 강제 종료까지 보호된다고 가정하거나 모든 화면에 이탈 경고를 등록한다.

## 실패 재현

편집 후 원래 값 복원, 저장 중 이탈, 저장 실패, 새로고침과 모바일 앱 전환·종료를 재현한다.

## 측정과 검증

미저장 판정, 저장 성공 후 이탈, 실패 시 내용 보존과 복귀 후 복구 내용을 확인한다.

## 재검토 조건

자동 저장·협업 편집·외부 파일 동기화가 추가되면 저장 완료와 충돌의 정의를 다시 정한다.

## 출처

- [MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event): 사용자 활성화·문구·모바일 제약과 필요한 때만 이벤트 등록.
- [Apple HIG Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts): iOS 편집 이탈의 저장·버리기·복귀 선택.
