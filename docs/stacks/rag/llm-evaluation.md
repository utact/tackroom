# LLM 평가

확인: 2026-09-27, Zheng 외 "Judging LLM-as-a-Judge"(NeurIPS 2023), Es 외 RAGAS(EACL 2024 데모), Miller "Adding Error Bars to Evals"(2024), Yao 외 τ-bench(2024), Panickssery 외(NeurIPS 2024)를 검색 요약으로 확인한 기준. 원문 접근이 막혀 수치는 요약에 인용된 값이다.

## 요약

LLM 평가는 "답이 좋아졌다"를 재현 가능한 숫자로 바꾸는 일이다.
RAG에서는 답이 틀린 원인이 검색 실패, 근거 없는 생성, 오래된 원문, 권한 위반 중 어디인지 **나눠서** 재야 고칠 곳이 보인다.
판정은 코드로 할 수 있는 것을 먼저 코드로 하고, 의미 판정은 모델에 맡기되 사람 판정과 맞춰 보정한다. 확률적인 시스템이므로 오차 막대 없이 비교하지 않는다.

## 문제 신호

- 프롬프트나 모델을 바꿨는데 좋아졌는지 몇 개 질문을 눈으로 보고 판단한다.
- RAG 답변이 틀렸다는 보고가 오지만 원인이 검색인지 생성인지 모른다.
- 같은 질문에 답이 매번 다르다.
- 평가 점수는 올랐는데 사용자 불만은 그대로다.
- 모델을 판정자로 쓰는데 그 판정을 믿어도 되는지 모른다.

## 기준선의 한계

기준선은 몇 개 질문을 사람이 돌려 보는 "느낌 평가"다.

- 표본이 작아 우연과 개선을 구분할 수 없다.
- 같은 질문도 실행마다 결과가 달라, 한 번의 실행으로 일반화할 수 없다.
- 평가 조건(모델 버전, 설정, 날짜)을 남기지 않아 나중에 비교할 수 없다.
- 실패 원인을 나누지 않아 "답이 틀렸다"에서 멈춘다.

## 원리

- **실패를 단계별로 나눈다.** RAG 답변의 오류는 대체로 넷이다. 정답 근거가 검색되지 않음(검색 실패), 근거는 있었는데 답이 근거를 벗어남(근거 없는 생성), 근거가 폐기된 판이었음(오래된 원문), 볼 수 없는 문서가 근거로 쓰임(권한 위반). 각각 고칠 곳이 다르다.
- **RAG 지표.** RAGAS는 정답 없이도 쓸 수 있는 지표로 근거 정밀도(context precision), 근거 재현율(context recall), 충실도(faithfulness), 답변 관련도를 제시했다. 충실도는 답변을 주장들로 쪼개 각 주장이 근거로 뒷받침되는 비율로 잰다.
- **판정 방식.** 코드 판정(정확 일치, 형식, 인용 ID가 검색 결과에 있는지, 권한 검사)은 싸고 재현된다. 모델 판정은 의미를 볼 수 있지만 편향이 있다. 사람 판정은 기준이지만 비싸다.
- **모델 판정의 편향.** Zheng 외는 위치 편향(먼저 제시된 답 선호), 장황함 편향(긴 답 선호), 자기 강화 편향(자기 계열의 답 선호)을 보고했다. 동시에 강한 판정 모델은 사람 선호와 80% 이상 일치해 사람끼리의 일치 수준에 닿았다고 보고했다. Panickssery 외는 모델이 자기 생성물을 알아보고 더 높게 평가한다고 보고했다.
- **오차 막대.** Miller는 평가 문항을 보이지 않는 모집단의 표본으로 보고, 평균에 중심극한정리 기반 표준오차를 붙이고, 한 문서에서 나온 여러 질문처럼 묶인 문항은 군집 표준오차를 쓰고, 두 모델 비교는 같은 문항의 대응 차이로 하라고 권한다.
- **반복 신뢰성.** τ-bench의 pass^k는 같은 과제를 k번 시도해 모두 성공할 확률이다. 성공률 p가 독립이면 p^k로 줄어든다. 90%는 k=8에서 약 43%가 된다(0.9^8 ≈ 0.43). 한 번 성공(pass@1)과 늘 성공(pass^k)은 다른 질문이다.

## 가치

평가를 설계하는 가치는 **변경이 실제로 나아졌는지, 어디가 나아졌는지를 말할 수 있게 하는 것**이다.

- 실패 유형별 수치로, 파싱·청킹·검색·프롬프트·모델 중 어디를 고칠지 정한다.
- 오차 막대가 있으면 "차이 없음"과 "좋아짐"을 구분해, 효과 없는 복잡도를 걷어낼 근거가 생긴다.
- 모델 교체나 버전 변경 때 같은 평가셋을 돌려 회귀를 잡는다.

## 트레이드오프와 리스크

- **평가셋 만들기가 비싸다.** 질의, 정답 근거, 정답 판정을 사람이 만들어야 한다. 작게 시작하면 통계적 힘이 약하다.
- **평가셋이 낡는다.** 문서와 사용자 질의가 바뀌면 평가셋이 실제 분포를 대표하지 않는다.
- **평가셋에 과적합된다.** 같은 평가셋으로 반복해서 고르면 평가셋에만 맞는 설정이 남는다. 일부를 따로 떼어 두고 가끔만 본다.
- **모델 판정은 편향된다.** 판정 모델이 평가 대상과 같은 계열이면 자기 선호가 섞인다. 판정 기준이 모호하면 판정도 흔들린다.
- **비용.** 모델 판정은 문항 수 × 반복 수 × 판정 호출이다. 평가를 CI에 넣으면 비용이 매번 든다.
- **숫자가 목표가 된다.** 충실도만 올리면 "모르겠다"만 답하는 시스템이 된다. 유보율과 정확도를 함께 봐야 한다.

## 대안과 경계

| 방식 | 쓸 때 |
|---|---|
| 코드 판정 | 정답이 정해진 문항(숫자, 날짜, 선택지), 형식 검사, 인용 ID 검증, 권한 검사. 항상 먼저 쓴다. |
| 모델 판정 | 의미 판정(충실도, 관련도, 완결성). 사람 판정과의 일치도를 먼저 잰다. |
| 사람 판정 | 기준 데이터 만들기, 모델 판정 보정, 분쟁 사례. 표본으로 한다. |
| 온라인 지표 | 운영 중 사용자 행동(채택, 재질의, 신고). 오프라인 평가를 대신하지 않고 보완한다. |
| 평가 프레임워크(RAGAS 등) | 지표 구현을 빌려 쓴다. 지표의 정의와 판정 프롬프트를 읽고 우리 기준에 맞는지 확인한다. |

## 깊이 있는 활용

- **평가셋에 실패 유형의 원인 정보를 함께 저장한다.** 문항마다 정답 문서·구간, 현행 판 여부, 필요한 권한을 기록해 두면, 검색 실패와 오래된 원문과 권한 위반을 코드로 판정할 수 있다.
- **검색과 생성을 따로 평가한다.** 검색 단계는 "정답 구간이 상위 k에 있는가"(Recall@k)를 코드로 재고, 생성 단계는 "정답 근거를 줬을 때 답이 맞는가"를 따로 잰다. 정답 근거를 강제로 넣은 생성 평가가 나쁘면 문제는 검색이 아니다.
- **인용을 검증한다.** 답변의 인용 ID가 실제 검색 결과에 있는지(코드), 인용 문장이 그 문서에 실제로 있는지(문자열 일치나 모델 판정)를 따로 본다.
- **유보를 평가 대상으로 넣는다.** 근거가 없는 질문, 서로 충돌하는 근거가 있는 질문을 평가셋에 넣고 "모른다고 답했는가"를 채점한다. 유보율과 정답률의 곡선으로 기준값을 정한다.
- **모델 판정은 보정한 뒤 쓴다.** 수백 문항을 사람이 판정하고 모델 판정과의 일치도(정확도, Cohen's kappa)를 잰다. 판정 기준을 구체적인 채점표로 쓰고, 비교 판정은 두 답의 순서를 바꿔 두 번 돌려 위치 편향을 상쇄한다. 판정 모델은 평가 대상과 다른 계열을 쓴다.
- **반복 실행한다.** 온도가 0이어도 결과가 흔들릴 수 있다. 문항마다 여러 번 돌려 문항별 성공률을 구하고, 운영에서 "항상 맞아야 하는" 문항은 pass^k로 본다.
- **대응 비교와 군집 오차를 쓴다.** 두 설정을 같은 문항에 돌려 문항별 차이의 평균과 표준오차를 낸다. 한 문서에서 여러 질문을 만들었다면 문서 단위로 군집 표준오차를 쓴다.
- **평가 조건을 기록한다.** 모델 이름과 버전, 프롬프트 해시, 검색 설정, 평가셋 버전, 날짜, 판정 모델을 결과와 함께 저장한다. 하네스 문서의 원칙과 같다.

## 임시방책의 신호

- 좋아 보이는 예시 몇 개로 변경을 승인한다.
- 틀린 답이 보고되면 그 질문만 프롬프트에 예외로 넣는다.
- 평가 점수를 한 번 실행한 평균 하나로 보고한다.
- 판정 모델과 평가 대상이 같은 모델이다.
- 평가셋을 운영 질문에서 한 번 뽑고 다시 보지 않는다.
- 충실도 점수를 올리려고 답을 짧게 만들거나 유보를 늘린다. 유보율은 보지 않는다.

## 실패 재현

- **검색 실패.** 정답 문서를 색인에서 빼고, 시스템이 근거 없이 답하는지 유보하는지 본다.
- **오래된 원문.** 같은 문서의 옛 판과 새 판을 넣고, 옛 판을 인용하는 비율을 잰다.
- **권한 위반.** 권한 없는 사용자로 질의해 권한 밖 문서가 검색되거나 인용되는지 코드로 검사한다.
- **판정 편향.** 같은 두 답의 순서를 바꿔 판정이 뒤집히는 비율을 잰다. 한 답을 내용은 같게 두고 길게 늘려 점수가 오르는지 본다.
- **비결정성.** 같은 문항을 20번 돌려 답이 갈리는 문항의 비율과 문항별 성공률 분포를 본다.

## 측정과 검증

- **평가셋 크기를 계획한다.** 기대하는 차이(예: 정확도 5%p)를 구분하려면 몇 문항이 필요한지 미리 계산한다. 문항이 수십 개면 큰 차이만 구분된다. 작은 표본에서는 중심극한정리 근사가 부정확하다는 지적도 있어, 부트스트랩을 함께 쓴다([측정 통계](../verify/statistics.md)).
- **보고 형식.** 지표마다 평균, 95% 신뢰구간, 문항 수, 반복 수를 쓴다. 비교는 차이와 그 신뢰구간으로 쓴다.
- **실패 유형 분포.** 틀린 답을 네 유형(검색 실패, 근거 없는 생성, 오래된 원문, 권한 위반)과 기타로 분류한 표를 매 평가마다 남긴다. 변경의 효과는 이 분포의 변화로 설명한다.
- **판정 신뢰도.** 모델 판정과 사람 판정의 일치도를 주기적으로 다시 잰다.
- **비용.** 문항당 생성 비용, 판정 비용, 지연을 품질과 같은 표에 둔다. 검증을 통과한 답 하나당 비용으로 본다.

## 재검토 조건

- 문서나 질의 분포가 바뀌었다. 평가셋을 갱신한다.
- 판정 모델을 바꿨다. 사람 판정과의 일치도를 다시 잰다.
- 평가 점수와 사용자 반응이 어긋난다. 평가셋이 실제 사용을 대표하는지 다시 본다.
