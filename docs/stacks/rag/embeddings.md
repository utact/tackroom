# 임베딩 모델 선택

확인: 2026-09-27, sentence-transformers(main) 문서와 예제, MTEB 관련 자료(검색 요약) 기준.

## 요약

임베딩 모델은 텍스트를 벡터로 바꿔 "뜻이 가까우면 벡터도 가깝게" 만든다.
의미 검색의 품질은 모델이 **우리 문서와 우리 질의의 언어·도메인에서** 얼마나 잘 구분하느냐로 정해진다.
공개 순위표는 후보를 좁히는 데만 쓰고, 선택은 자체 평가셋으로 한다. 차원, 정밀도, 입력 한도, 접두어 규칙, 비용이 함께 걸린 결정이다.

## 문제 신호

- 의미 검색을 붙였는데 한국어 질의나 사내 용어에서 엉뚱한 문서가 나온다.
- 벡터 저장 크기나 검색 지연이 문제다.
- 임베딩 API 비용이 문서 수에 비례해 커진다.
- 모델을 바꾸고 싶은데 기존 벡터를 어떻게 할지 모른다.

## 기준선의 한계

기준선은 "잘 알려진 영어 중심 범용 모델 하나를 기본 설정으로" 쓰는 것이다.

- 영어 벤치마크 점수가 한국어나 도메인 문서의 성능을 보장하지 않는다.
- 모델마다 질의와 문서에 붙여야 하는 접두어나 지시문이 있다. 빼먹으면 성능이 떨어진다.
- 입력 한도를 넘는 텍스트는 잘린다.
- 차원이 크면 저장과 검색 비용이 비례해서 는다.

## 원리

- **bi-encoder.** 질의와 문서를 따로 벡터로 만든다. 문서 벡터를 미리 계산해 색인할 수 있어 대규모 검색이 가능하다. 대신 질의와 문서를 함께 보는 cross-encoder보다 덜 정확하다([하이브리드 검색과 리랭킹](../search/hybrid-rerank.md)).
- **비대칭 검색과 지시문.** 짧은 질문과 긴 문단을 맞추는 검색은 비대칭이다. 많은 모델이 질의와 문서에 서로 다른 접두어나 지시문(prompt)을 붙이도록 학습됐다. sentence-transformers는 `encode(..., prompt=...)`로 지시문을 넣는 예를 보여준다.
- **입력 한도.** 모델마다 최대 토큰 수가 있고, 넘으면 잘린다. 문서의 비교 예시는 MiniLM 256, MPNet 384, BGE-base 512, BGE-M3 8,192 토큰이다.
- **거리.** 모델이 정규화된 벡터를 내면 내적과 코사인 유사도가 같은 순서를 준다. 모델이 학습한 거리 함수를 쓴다.
- **Matryoshka 표현.** Matryoshka 손실로 학습한 모델은 벡터 앞부분만 잘라 써도 성능이 크게 떨어지지 않는다. 작은 벡터로 넓게 찾고 전체 벡터로 다시 정렬하는 2단계에 쓴다.
- **양자화.** 이진 양자화는 float32를 1비트로 줄여 메모리와 저장을 32배 줄인다. sentence-transformers 문서는 float32 질의 벡터로 다시 점수를 매기는 단계를 더하면 검색 성능의 약 96%를 유지하면서 속도도 최대 32배 빨라진다고 보고한다. int8 스칼라 양자화는 보정 데이터셋이 성능을 크게 좌우한다.

## 가치

모델을 제대로 고르는 가치는 **검색 품질과 비용을 같은 평가 위에서 맞바꾸는 것**이다.

- 우리 데이터로 잰 점수로 고르면, 순위표 1위 모델보다 작고 싼 모델이 충분한 경우를 찾는다.
- 차원 축소와 양자화로 저장·메모리 비용을 몇 분의 일로 줄이면서 품질 손실을 수치로 통제한다.
- 모델 버전을 데이터에 기록하면 모델 교체가 안전한 이행 작업이 된다.

## 트레이드오프와 리스크

- **공개 벤치마크는 과적합된다.** sentence-transformers 문서도 MTEB를 학습 중 평가에 쓰면 공개 벤치마크에 과적합될 위험이 있다고 적는다. 순위표 점수는 우리 데이터의 점수가 아니다.
- **모델을 바꾸면 전부 다시 계산한다.** 다른 모델의 벡터끼리는 비교할 수 없다. 문서 수가 많으면 재계산 비용과 시간이 크다. 이행 중에는 두 벡터를 함께 보관해야 한다.
- **API 모델은 바뀌거나 사라질 수 있다.** 외부 임베딩 API는 모델 폐기, 가격 변경, 데이터 전송 정책의 영향을 받는다. 자체 호스팅은 GPU와 운영 부담이 생긴다.
- **큰 모델은 적재와 질의가 느리다.** 차원과 파라미터가 크면 문서 적재 처리량이 떨어지고 질의 지연이 는다.
- **양자화와 차원 축소는 손실이다.** 다시 점수 매기기 없이 쓰면 손실이 커진다. 손실이 우리 데이터에서 얼마인지 재야 한다.
- **긴 입력 한도가 곧 좋은 품질은 아니다.** 한도가 길어도 긴 청크 하나에 여러 주제가 섞이면 벡터가 흐려진다. 청크 설계는 [청킹](chunking.md)의 몫이다.

## 대안과 경계

| 선택지 | 고를 때 |
|---|---|
| 외부 API 모델 | 빠르게 시작하고, 데이터 전송이 허용되고, 문서 수가 적당하다. |
| 오픈 모델 자체 호스팅 | 데이터를 밖으로 보낼 수 없거나, 문서가 많아 API 비용이 크거나, 모델을 고정해야 한다. |
| 도메인 미세 조정 | 평가셋에서 공개 모델이 부족하고, 질의-문서 쌍 데이터가 있다. |
| 희소(sparse) 모델, BM25 | 용어 일치가 중요하다. 의미 검색과 결합한다. |

## 깊이 있는 활용

- **순위표로 후보 서너 개를 고르고, 자체 평가셋으로 정한다.** MTEB·MMTEB의 검색 과제와 한국어 과제 점수로 후보를 좁힌 뒤, 우리 질의와 정답 문서로 Recall@k와 nDCG@10을 잰다. 모델 크기, 차원, 질의 지연을 같은 표에 둔다.
- **모델 카드의 접두어 규칙을 지킨다.** 질의와 문서에 다른 지시문을 붙이는 모델이면 두 쪽에 각각 넣는다. 평가도 같은 규칙으로 한다.
- **입력 한도를 청크 설계의 상한으로 쓴다.** 청크를 모델 토크나이저로 재서 한도 안에 넣는다.
- **2단계로 비용을 줄인다.** 이진 양자화나 Matryoshka로 줄인 작은 벡터로 넓게 후보를 뽑고, 원래 정밀도의 벡터로 다시 점수를 매긴다. sentence-transformers 예제는 4,100만 건을 이진 인덱스(메모리)와 int8 인덱스(디스크)로 나눠 메모리 5.2GB로 검색한다.
- **벡터와 함께 모델 식별자를 저장한다.** 모델 이름, 버전, 지시문, 정규화 여부를 벡터 옆에 기록한다. 모델 교체는 새 컬럼이나 새 색인에 채운 뒤 평가셋으로 확인하고 전환한다.
- **질의 임베딩을 캐시한다.** 같은 질의가 반복되면 질의 벡터를 캐시해 지연과 비용을 줄인다.

## 임시방책의 신호

- 순위표 1위 모델을 골랐다는 것이 선택 근거의 전부다.
- 질의에만 접두어를 붙이거나, 아무 데도 붙이지 않는다.
- 검색 품질이 나쁘자 차원이 더 큰 모델로 바꾼다. 평가셋은 없다.
- 모델을 바꾸면서 일부 문서만 다시 임베딩한다.
- 양자화를 켜고 다시 점수 매기기 없이 쓴다.

## 실패 재현

- **언어·도메인 격차.** 같은 평가셋에서 영어 중심 모델과 다국어 모델, 한국어 특화 모델의 Recall@k를 비교한다. 사내 용어 질의만 따로 떼어 본다.
- **접두어 누락.** 지시문을 붙인 경우와 뺀 경우의 검색 지표를 비교한다.
- **잘림.** 입력 한도를 넘는 문서 뒷부분의 내용으로 질의해 검색되지 않는 것을 확인한다.
- **모델 혼용.** 다른 모델로 만든 벡터를 같은 색인에 섞어 검색이 무너지는 것을 확인한다.
- **양자화 손실.** float32, int8, 이진, 이진 + 다시 점수 매기기의 지표를 비교한다.

## 측정과 검증

- **평가셋.** 실제 질의 표본과 관련 문서 판정을 모은다. 질의 유형(짧은 키워드, 자연어 질문, 사내 용어, 숫자 포함)별로 나눠 본다.
- **지표.** Recall@k(검색 단계), nDCG@10과 MRR(순위), 질의 지연 p50·p99, 문서당 적재 시간, 벡터 저장 크기, 문서 100만 건당 비용.
- **통계.** 모델 간 비교는 같은 질의 집합의 대응 비교다. 질의 단위 부트스트랩으로 차이의 신뢰구간을 내고, 평가셋이 작으면 결론을 유보한다([측정 통계](../verify/statistics.md)).
- **하류 확인.** 최종 결정 전에 RAG 답변 평가([LLM 평가](llm-evaluation.md))로 근거 검색률과 답변 정확도가 실제로 오르는지 본다.

## 재검토 조건

- 문서나 질의의 언어·도메인 분포가 바뀌었다.
- 새 모델이 나와 후보 목록이 바뀌었다. 같은 평가셋으로 다시 잰다.
- 저장 비용이나 지연이 목표를 넘는다. 양자화와 차원 축소를 검토한다.
