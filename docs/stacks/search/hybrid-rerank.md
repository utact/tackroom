# 하이브리드 검색과 리랭킹

확인: 2026-09-27, Elasticsearch v9.5.4 RRF 문서, pgvector v0.8.6 README, sentence-transformers 문서(main), BEIR 논문(검색 요약) 기준.

## 요약

키워드 검색(BM25 등)은 정확한 단어 일치에 강하고, 의미 검색(임베딩 유사도)은 표현이 달라도 뜻이 같은 것을 찾는다.
하이브리드 검색은 둘의 결과를 합치고, 리랭킹은 합친 후보 상위 수십~백 개를 더 비싸고 정확한 모델(cross-encoder)로 다시 정렬한다.
어느 조합이 나은지는 데이터와 질의에 따라 다르므로, **같은 평가셋으로 비교한 뒤 고르는 것**이 이 기법의 본질이다.

## 문제 신호

- 의미 검색만 쓰니 제품 코드, 고유명사, 약어, 숫자가 들어간 질의를 놓친다.
- 키워드 검색만 쓰니 표현이 다른 질문("환불" ↔ "돈을 돌려받고 싶어요")을 놓친다.
- RAG 답변이 틀렸는데 원인을 보니 근거 문서가 상위 k개에 없었다.
- 상위 몇 개의 순서가 중요하다(LLM에 넣는 문서 수가 제한된다).

## 기준선의 한계

기준선은 키워드 검색 하나, 또는 의미 검색 하나다.

- BEIR 벤치마크(18개 데이터셋)에서 BM25는 도메인 적응 없는 여러 신경망 검색기보다 도메인 밖에서 강했다. 의미 검색만이 항상 낫다는 가정은 틀리다.
- 반대로 키워드 검색은 동의어와 다른 표현을 못 찾는다.
- 한 방식의 점수만으로는 서로의 약점을 보완하지 못한다.

## 원리

- **두 검색기의 점수는 비교할 수 없다.** BM25 점수와 코사인 유사도는 척도가 다르다. 그래서 점수를 더하지 않고 순위로 합치는 방법이 쓰인다.
- **RRF(Reciprocal Rank Fusion).** 각 결과 목록의 순위 `r`로 `Σ 1/(k + r)`을 계산한다(`k` 기본 60). 점수 조정 없이 서로 다른 관련도 지표를 합친다. 원 논문은 Cormack 외(SIGIR 2009)다.
- **점수 정규화 결합.** 각 점수를 최소-최대 정규화 등으로 맞춘 뒤 가중합한다. 가중치를 평가셋으로 조정해야 한다.
- **bi-encoder와 cross-encoder.**
  - bi-encoder는 질의와 문서를 따로 벡터로 만들어 미리 색인하므로 빠르다.
  - cross-encoder는 쌍마다 함께 넣어 점수를 내므로 대개 더 정확하지만 느리다. 그래서 검색기가 고른 상위 k를 다시 정렬하는 데 쓴다.
- **2단계 파이프라인.** 빠른 검색기로 넓게(예: 100개) 모으고, 느리고 정확한 리랭커로 좁힌다(예: 상위 5개). BEIR는 리랭킹과 late-interaction 모델이 평균적으로 가장 좋은 성능을 냈지만 계산 비용이 높았다고 보고했다.

## 가치

이 기법의 가치는 **재현율은 싼 검색기 여럿으로 넓히고, 정밀도는 비싼 모델 하나로 올리는 분업**이다.

- 키워드와 의미 검색의 실패가 서로 다른 질의에서 일어나므로, 합치면 상위 후보에 정답이 들어올 확률이 오른다.
- 리랭커는 후보 수십 개에만 쓰므로 비용을 통제하면서 상위 순서를 크게 개선한다.
- RRF는 조정할 것이 거의 없어 첫 결합으로 쓰기 좋다.

## 트레이드오프와 리스크

- **지연과 비용이 는다.** 검색기 두 개를 돌리고, 리랭커는 후보 수만큼 모델을 호출한다. GPU나 외부 API 비용이 생긴다.
- **개선이 보장되지 않는다.** 한 검색기가 훨씬 나쁘면 합칠 때 오히려 순위가 흐려질 수 있다. 평가 없이 넣으면 "복잡해졌는데 좋아졌는지 모르는" 상태가 된다.
- **리랭커는 후보에 없는 문서를 살리지 못한다.** 검색 단계에서 놓친 정답은 리랭커가 되살릴 수 없다. 재현율 문제를 리랭커로 풀려는 것은 틀린 처방이다.
- **도메인 차이.** 공개 데이터로 학습한 리랭커와 임베딩 모델이 한국어나 특정 도메인(법률, 의료, 사내 용어)에서 기대만큼 동작하지 않을 수 있다.
- **권한 필터는 검색 단계에서 건다.** 리랭킹 뒤에 걸면 상위 결과가 빈다. 모든 검색기에 같은 권한 필터를 넣어야 한다.
- **두 색인의 동기화.** 키워드 색인과 벡터 색인이 다른 저장소에 있으면, 한쪽만 갱신된 문서가 한쪽 결과에만 나온다.

## 대안과 경계

| 대안 | 고를 때 |
|---|---|
| 키워드 검색 하나 | 질의가 코드, 이름, 정확한 용어 중심이고 평가에서 의미 검색이 더하는 것이 없다. |
| 의미 검색 하나 | 질의가 자연어 질문 중심이고 평가에서 키워드 결합이 더하는 것이 없다. |
| 질의 재작성, 확장 | 질의가 짧거나 모호하다. 동의어 사전이나 LLM으로 질의를 늘린다. 비용과 지연을 함께 잰다. |
| late-interaction(ColBERT 계열) | 리랭커에 가까운 정확도를 색인 가능한 방식으로 원한다. 색인 크기가 커진다. (미검증: 이 조사에서는 비교하지 않았다.) |

어디서 합칠지는 저장소에 따라 정한다.
[Elasticsearch](elasticsearch.md)는 RRF retriever로 한 요청 안에서 합친다.
[pgvector](pgvector.md)는 전문 검색(`tsvector`)과 벡터 검색을 한 DB에서 돌리고 SQL이나 애플리케이션에서 RRF로 합친다.

## 깊이 있는 활용

- **검색 단계는 재현율로, 리랭킹 단계는 순위 지표로 평가한다.** 검색 단계의 목표는 "정답이 후보 100개 안에 있는가"(Recall@100)이고, 리랭킹의 목표는 "정답이 맨 위 몇 개에 있는가"(nDCG@10, MRR)다. 두 지표를 섞으면 어느 단계가 문제인지 모른다.
- **RRF에서 시작하고, 평가셋으로 가중 결합과 비교한다.** RRF는 조정이 필요 없는 강한 출발점이다. 평가셋이 충분하면 정규화 가중합의 가중치를 찾아 비교한다.
- **후보 수(window)를 곡선으로 정한다.** 후보 수를 20, 50, 100, 200으로 바꿔 최종 품질과 리랭킹 지연을 함께 그리고, 품질이 평평해지는 지점을 고른다. RRF의 `rank_window_size`가 이 값이다.
- **질의 유형별로 나눠 본다.** 고유명사·코드 질의, 자연어 질문, 긴 질의, 오타 질의로 평가셋을 나누면, 하이브리드가 어느 유형에서 이기고 지는지 보인다. 평균만 보면 유형별 손실이 가려진다.
- **리랭커는 한국어와 도메인 데이터로 확인한다.** 다국어 리랭커 여러 개를 같은 평가셋에 돌려 고른다. 필요하면 도메인 질의-문서 쌍으로 미세 조정한다.
- **리랭커 점수로 "모름"을 판단한다.** 상위 문서의 점수가 평가셋에서 정한 기준보다 낮으면 답변을 유보한다([LLM 평가](../rag/llm-evaluation.md)).

## 임시방책의 신호

- 의미 검색이 코드나 이름을 못 찾자, 특정 질의 패턴에만 `LIKE` 검색을 덧붙인다.
- 평가셋 없이 리랭커를 붙이고 "좋아졌다"고 한다.
- 두 검색기의 원점수를 그대로 더한다.
- 정답이 후보에 없는데 리랭커 모델을 계속 바꾼다.
- 권한 필터를 리랭킹 뒤에 건다.

## 실패 재현

- **유형별 실패.** 코드·고유명사 질의에서 의미 검색이, 다른 표현의 질의에서 키워드 검색이 정답을 놓치는 사례를 평가셋에 넣고 각각의 Recall@k를 본다.
- **리랭커의 한계.** 정답을 검색 후보에서 일부러 빼고 리랭커가 복구하지 못하는 것을 확인한다. 검색 단계 재현율이 상한이라는 점을 수치로 보인다.
- **척도 불일치.** 원점수를 더한 결합과 RRF를 같은 평가셋에서 비교한다.
- **동기화 불일치.** 한 색인만 갱신된 상태에서 검색해 결과가 한쪽에만 나오는 것을 본다.

## 측정과 검증

- **평가셋을 먼저 만든다.** 실제 질의 표본과 관련 문서 판정을 수십 개로 시작해 수백 개로 늘린다. 모델 판정이면 사람 판정과의 일치도를 먼저 잰다.
- **지표.** 검색 단계는 Recall@k, 최종 순위는 nDCG@10과 MRR을 쓴다. 질의 유형별로 따로 보고한다.
- **통계.** 같은 질의 집합의 비교이므로 대응 표본 검정(부호, 윌콕슨)이나 질의 부트스트랩으로 신뢰구간을 낸다([측정 통계](../verify/statistics.md)).
- **비용과 지연.** 질의당 지연 p50, p99와 질의당 비용(리랭커 호출, GPU 시간)을 품질 지표와 함께 표로 남긴다.
- **온라인 지표.** 운영에서는 클릭, 답변 채택, 재질의 비율을 함께 보되, 오프라인 평가셋을 기준으로 삼는다.

## 재검토 조건

- 평가에서 한 검색기만으로도 결합과 차이가 없다. 단순한 쪽으로 돌아간다.
- 리랭킹 지연이나 비용이 요구를 넘는다. 후보 수를 줄이거나 작은 리랭커로 바꾼다.
- 질의 분포가 바뀌었다(새 기능, 새 사용자층). 평가셋을 갱신하고 다시 잰다.
